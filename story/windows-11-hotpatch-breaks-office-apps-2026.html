Microsoft Confirms Its November Windows 11 Hotpatch Can Stop Office and Other Apps From Launching

The no-restart security update KB5132043 is breaking apps on enterprise PCs managed through Windows Autopatch, and Microsoft's temporary fix is a registry edit while a permanent repair is prepared.

ONOrbit News NetworkNov 20, 2026 · 4 min readFacebookX

Microsoft has confirmed that its November 2026 hotpatch for Windows 11 can stop Microsoft Office and third-party applications from installing, launching or running normally. The company told IT administrators about the problem in a service alert on November 19, and shared a temporary registry workaround while it works on a permanent fix.

The update at the center of the problem is KB5132043, released on November 10 for Windows 11 versions 24H2, 25H2 and 26H2, taking them to OS builds 26100.9911, 26200.9911 and 26300.9911. Hotpatch updates deliver security fixes without requiring a device restart, which is why they are popular with IT teams managing large fleets of office PCs. In this case, the convenience came with a catch.

Affected devices show an error reading ERROR_ALLOTTED_SPACE_EXCEEDED, code 0xC0000099, when installing, opening or running certain applications. Microsoft's analysis links the failures to applications that load the 32-bit version of the Windows Installer library, known as msi.dll. The issue can happen more frequently with 32-bit applications, but it can also occur for 64-bit applications under certain conditions. One administrator traced the fault to msi_hotpatch.dll, a file included in the KB5132043 update.

The scope of the problem is narrower than it first sounds. Microsoft says the known issue should not affect systems that installed the standard November 2026 Patch Tuesday security updates. It applies only to devices that received the hotpatch updates pushed through Windows Autopatch, the company's cloud-based enterprise service that automates Windows and Microsoft 365 software and security updates. That means the trouble is concentrated in enterprise environments rather than typical home PCs.

Until a fix is available, Microsoft has told administrators to edit the Windows Registry to raise the HotPatchTableSize value to 2000, then restart the device. The steps run through the registry key at HKEY_LOCAL_MACHINE, SYSTEM, CurrentControlSet, Control, Session Manager, Memory Management. Microsoft warns administrators to back up the registry before modifying it, so the change can be reversed if something goes wrong. Administrators watching for a permanent fix should follow the Windows release health dashboard under service alert WI1559710.

The hotpatch problem is not the only trouble reported with November's Windows updates. Administrators have also reported printing failures, Citrix Workspace refusing to launch and Sage 50 accounting software crashing after installing KB5132043 or the related cumulative update KB5132061, according to Neowin's coverage of the update problems. Microsoft has separately confirmed printing trouble with KB5132061 for documents containing images with zero height or width at the selected printing resolution.

The timing is awkward for Microsoft. Hotpatching was turned on by default earlier this year for eligible Windows devices managed through the Microsoft Graph API and Microsoft Intune, after the May 2026 Windows security updates were installed. The pitch was that security fixes could land without interrupting work with a restart. A bug that stops Office from opening undermines that pitch directly, since the update meant to protect the workday ends up breaking it.

For IT teams, the practical question is what to do with the rest of November's patches. The standard Patch Tuesday update is not affected by this particular bug, so machines on the normal update track can proceed. But organizations that adopted hotpatching through Autopatch now have to decide whether to apply the registry workaround across their fleet, pause hotpatching, or wait for Microsoft's permanent fix, which has no announced date yet.

The incident is the latest in a rough month for Microsoft's update pipeline. The November security updates arrived on November 10, and Microsoft has already had to ship emergency fixes for a Windows activation bug introduced by the same round of patches, after administrators found the standard activation tool failing with error 0x80041008. For a company whose enterprise customers depend on updates landing quietly, November 2026 has been anything but quiet.

Why it matters: This matters because hotpatching was supposed to make Windows updates boring. Microsoft turned it on by default for managed devices this year on the promise that security fixes would arrive without a restart and without drama, and the first big test of that promise has produced the opposite: Office refusing to open on enterprise PCs, with a registry edit as the interim answer. The bug itself is narrow, hitting only Autopatch-managed machines on the hotpatch track, but the trust damage is wider. IT administrators who adopted hotpatching to save their users a reboot now have to weigh whether the convenience is worth the risk, and every future hotpatch will be greeted with more caution until Microsoft shows it can ship one cleanly. Watch the release health dashboard for the permanent fix, and watch whether Microsoft pauses or slows the hotpatch rollout in response.
