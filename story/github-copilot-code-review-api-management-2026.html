GitHub Lets Admins Run Copilot Code Review by API, From the Whole Company Down to One Repo

A November 6 changelog update puts Copilot code review settings behind REST and GraphQL APIs, adds clearer attribution for AI comments, and shows the credits each review burns.

ONOrbit News NetworkNov 8, 2026 · 4 min readFacebookX

GitHub has expanded Copilot code review with new management controls that let administrators run the AI reviewer through application programming interfaces. In a changelog entry published on November 6, the company said Copilot code review settings can now be managed through the REST and GraphQL APIs, from enterprise policy down to individual repositories.

The change matters because code review has become one of the most widely used parts of GitHub Copilot, and until now its settings were largely managed by clicking through web pages. Large organizations with hundreds of repositories can now set policy in code, apply it consistently, and change it without opening the settings screen for every single repo.

The new controls follow the three levels of GitHub administration. Enterprise administrators can enable or disable code review for all organizations, or leave the choice to organization administrators. Organization administrators can manage review enablement, the default review effort and the runner configuration, while repository administrators control the review effort and whether reviews use custom instructions and tools connected through the Model Context Protocol.

There is one authentication catch that administrators will need to plan around. The enterprise and organization settings endpoints do not support GitHub Apps or fine-grained personal access tokens, while the repository settings endpoints support both, with read permission needed to view settings and write permission needed to update them. Settings managed at the enterprise level cannot be overridden further down the chain.

The update also makes Copilot's reviews easier to audit. API responses now carry explicit attribution fields that identify Copilot's reviews and comments, the review effort used, and the skills, MCP servers and custom instructions Copilot reported as sources for a comment. For teams that need to know why an AI reviewer flagged a line of code, that paper trail is a meaningful improvement.

The review overview comment that Copilot posts on a pull request is now more compact, grouping the effort level, survey results and findings so the important items are easier to spot. Balanced reviews, the built-in default, now use three reviewer models, with another model combining their findings, in a setup designed to catch more issues while filtering out repeated ones.

Cost transparency is part of the update too. Copilot code review agent sessions now show the AI credits consumed in a review, so teams can see what each review costs instead of discovering it on a bill. GitHub's documentation estimates that a Lite review typically costs between $0.05 and $1, a Balanced review between $0.25 and $5, and a Max review between $1.50 and $25, with averages of about $0.25, $1.50 and $10 respectively.

Reliability also got attention. The update includes fixes for billing, automatic reviews and reliability, including automatic retries and the preservation of billing and preview settings when administrators disable and re-enable code review. The repository rule that automatically requests Copilot code review now supports a bypass list, so exempt actors will not receive an automatic review.

The updates are available to Copilot Pro, Pro+, Max, Business and Enterprise plans. They arrive as part of a busy week for Copilot, which also gained support in JetBrains Air and in Xcode's built-in coding assistant, now in public preview starting with Xcode 27.3 beta, along with an Agent Merge feature that lets Copilot merge a pull request once it is ready.

The direction of travel is clear. GitHub rebuilt Copilot around agents at its Universe event on October 28, with Copilot Fusion generally available and deeper review tiers in preview. The November 6 update turns that vision into something administrators can actually govern, with APIs for control, attribution for accountability and credit counts for cost. For teams already letting AI review their code, the question is no longer whether the reviewer works, but whether it can be managed at scale.
