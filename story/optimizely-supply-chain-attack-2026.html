Malware Planted Through Optimizely Hit 178 Major Websites, Including Zoom, the BBC and CNN

Visitors to the websites of 178 organisations were served malicious code on Monday after attackers slipped JavaScript into Optimizely's A/B-testing platform, swapping crypto wallet addresses, skimming card details and targeting older iPhones.

ONOrbit News NetworkNov 17, 2026 · 6 min readFacebookX

Visitors to some of the world's biggest websites were served malicious code on Monday, November 16, after attackers planted JavaScript inside Optimizely, the A/B-testing platform those sites use to try out different versions of their pages. Security researcher Scott Helme, whose firm Report URI monitors the scripts websites run, found malicious code in 188 Optimizely JavaScript files belonging to 178 organisations, after checking 1,611 scripts used by the platform. BleepingComputer, which independently confirmed the attack, reported that the affected sites included Zoom, CNN, Fox News, the BBC, Salesforce and GitLab.

Optimizely is a digital experience and experimentation platform that organisations use to test and personalise their websites, with its JavaScript files loaded into customers' webpages to deliver that functionality. That trusted position is what made the attack so far-reaching: the malicious code did not arrive through the BBC's, CNN's or Zoom's own servers, but through a script those sites already load from Optimizely on every page. According to Helme's analysis, attackers inserted malicious code into Optimizely customer projects, causing JavaScript files hosted on the company's content delivery network to load malware on the websites that used the service.

BleepingComputer independently confirmed that the malicious script loaded, or attempted to load, on numerous affected websites using scans recorded by urlscan.io, including Zoom, KLM, GitLab, the BBC, CNN, American Girl, Smartsheet and Salesforce. Other affected sites included Fox News, Mutual of Omaha, American Eagle, Air France, Change.org, HSBC Insurance, Bitly, IG and UNICEF USA. Gizmodo's account also named Peacock, IKEA, NPR, the ASPCA and Invisalign among the affected brands.

The injected code was designed to pull in a second malicious script from an attacker-controlled address, 1688360[.]cc/track.js. Some of the infected files pointed at that address directly, while others hid it with Base64 encoding decoded by JavaScript's atob() function, and Helme found one variation that could run an embedded copy of the malicious code if the remote script was blocked. Once running, the payload had several jobs: it watched webpages for cryptocurrency wallet addresses and replaced them with addresses controlled by the attackers, it searched for credit card numbers, expiry dates and security codes typed into webpages and tried to send them to the attackers, and it loaded additional code aimed at iPhones and iPads. Helme identified those secondary payloads as the Coruna and DarkSword exploit kits, which target different iOS versions. The script could also collect browser cookies, webpage addresses and screenshots.

The crypto theft worked. Helme's investigation found that cryptocurrency wallets embedded in the track.js script received approximately $7,000 in transactions on November 16, and Report URI put the figure at about $7,040 as of 19:25 UTC on November 16, all within roughly nine hours. The largest share was bitcoin: 0.08298 BTC, worth about $5,380, across seven transactions. Litecoin added about $762, TRON about $719, Ethereum about $100 and BNB Smart Chain about $82. Those five figures add up to about $7,043, matching the reported total of roughly $7,040. How many payment cards or cookies were captured is not known, so the full damage is still unclear.

The earliest Optimizely script hijacking Helme traced was in the early morning of November 16, and the code stayed live for most of the day. Cleanup moved quickly once the attack was spotted: Helme reported that only one of the 188 previously compromised files still contained malicious code as of 21:52 UTC on November 16, meaning 187 of the 188 infected scripts had been cleaned within about a day of the first injection being found.

Optimizely confirmed the incident after the attack was uncovered. Spokesperson Victoria Johnson told Gizmodo that the company had identified a security incident in which an unauthorised party exploited a vulnerability in the Experimentation account signup flow, and that all affected customers had been notified. The company's statement confirmed that the unnamed party added malicious JavaScript to some customer projects, and said Optimizely had blocked access to the vulnerable path and deployed a fix.

What is still not known is how the attackers got write access to so many different customer projects in the first place. BleepingComputer reported that it remains unclear whether the attack involved a compromise of Optimizely's infrastructure, stolen credentials, or another method of gaining unauthorised access, and that it is also unknown how many website visitors were exposed to the malware. Optimizely has not said publicly how a flaw in a signup flow gave an outsider write access to existing customers' projects, or whether any customer data held by Optimizely was accessed.

For ordinary visitors, the practical risk is narrow but real. Anyone who visited one of the affected sites on November 16 and sent cryptocurrency that day should check that the payment went to the intended wallet address, since the clipboard-hijacking code was built to swap in the attackers' addresses. Card details typed into payment forms on the affected sites that day may also have been captured, so checking recent card statements is prudent.

One note of caution comes from Gizmodo's own reporting: the findings were first published by Report URI, a company that sells tools for detecting malicious scripts, so it has a commercial interest in this kind of story. But the core facts no longer rest on Report URI alone. BleepingComputer verified the malicious script loading on the affected sites itself, and Optimizely has confirmed the incident and the flaw behind it. The attack is a reminder that the most dangerous code on a trusted website is often not the site's own: a single supplier with permission to run JavaScript on hundreds of major sites can become a doorway into all of them at once.

Why it matters: This attack matters because it breaks the assumption most people make when they visit a familiar website: that the site itself is the only code they are trusting. None of the 178 organisations had their own systems breached, yet their visitors were still exposed, because a single third-party testing tool had permission to run code on their pages. That is the supply-chain risk in its purest form, and it is why the cleanup speed matters as much as the modest $7,040 crypto haul: the same doorway could have carried a far larger payload. Expect affected companies to tighten which outside scripts they allow, and expect regulators and customers to ask harder questions about how a signup-flow flaw gave an outsider write access to so many customer projects.

Reporting: BleepingComputer · Gizmodo
